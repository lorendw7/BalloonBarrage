# Original paint-spray style candidate

`Assets/StudioArtPack/PaintSprayStyle20261021/Textures/PaintSprayStyle_Atlas_v2.png` is a newly generated transparent 2-by-2 sprite atlas for an energetic paint-shooter presentation. It borrows only broad visual qualities: saturated runtime color, chunky liquid silhouettes, directional motion and immediate hit readability. It does not reproduce another game's assets, characters, UI, typography, weapons, named iconography or territory rules.

The four neutral white/gray cells are prepared for runtime tinting:

| Cell | Sprite name | Intended visual role |
|---|---|---|
| Top left | `NozzleJetTopLeft` | brief accepted-shot nozzle flash |
| Top right | `ViscousStreakTopRight` | optional fast directional accent |
| Bottom left | `DropletClusterBottomLeft` | small airborne secondary droplets |
| Bottom right | `ImpactSplashBottomRight` | short non-persistent hit accent |

The production `PrototypeScene` uses the dedicated transparent `PaintNozzleJet` material on `MuzzleSpray`. Texture Sheet Animation now chooses per particle between the atlas's two upper directional silhouettes instead of repeating one cell. The looping system emits 260 particles per second with no burst, using a concentrated 0.65-degree cone and 0.006-unit emitter radius, fixed 32-unit speed, 0.10-to-0.20-unit size and a 288-particle cap. A subtle 0.025-strength, 1.6-frequency scrolling noise adds liquid irregularity without widening the authoritative hit volume. A size-over-lifetime envelope starts each streak at 65%, swells quickly to 108%, then contracts to 40%; color-over-lifetime holds full opacity through roughly 76% of particle life before fading to zero. Its stretched-billboard renderer uses a 0.01 speed scale and 1.35 length scale so adjacent droplets overlap into a dense core without producing an oversized backward tail.

The October 25 gun-art correction moves only the `MuzzleSpray` visual child 0.14 local units forward from `Muzzle`. The logical `Muzzle` transform used by the learner's finite SphereCast remains unchanged. This separates the first stretched billboard from the nozzle and reduces the impression that paint passes through the weapon, while preserving aiming, hit sampling, range and scoring. Acceptance still requires a first-person held-fire check because prefab configuration alone cannot prove the final camera-space silhouette.

## Continuous spray presentation

The learner-saved `PlayerShooter` implementation no longer instantiates a flying projectile for accepted shots. Held fire keeps the production six-samples-per-second cadence and performs an immediate 0.3-radius SphereCast from the muzzle over a 30-unit range. This forgiving logical volume is deliberately wider than the enabled 0.13-radius balloon collider. Balloon hits retain the saved rhythm bonus path; non-balloon hits delegate to the existing paint-pattern data on `PaintDrop3D_Teal.prefab` to create static surface marks. Production defaults to pigment index 0, teal, so the stream and direct marks agree with the gun's dominant accent. The serialized index still exposes all eight coordinated pigment groups for a future deliberate theme switch. Direct wall deposits use a 4:2:1 spray/burst/drip weight; floor deposits use a 3:2 spray/burst weight and exclude gravity-oriented drips. Spray marks settle at 0.95-to-1.40 scale, bursts at 0.80-to-1.15 and drips at 0.90-to-1.15. Broad swoosh, dry-brush and starburst silhouettes remain available to the legacy projectile presentation but are omitted from direct deposits because repeated samples made them read as detached fragments or bullet holes.

Each deposited surface mark receives a visual-only `PaintMarkImpactPulse`. It begins at 48% of its randomized settled scale, swells to 114%, and settles to 100% over 0.16 seconds. The short-lived component then destroys itself without removing or continually updating the persistent mark.

The stream uses Local simulation space so existing droplets follow the current nozzle direction rather than leaving a bent world-space trail during fast aim changes. While firing, `PlayerShooter` derives visual reach from the existing cursor ray contact, converts that distance to lifetime at 32 units per second and removes any buffered particle beyond the shortened endpoint. Releasing, pausing or losing the valid fire state clears the visual stream immediately. Particle collision remains disabled; authoritative balloon hits, scoring and persistent-paint placement still use the finite six-per-second SphereCast path rather than adding another per-frame gameplay query.

The particle renderer uses sorting order 10000. Background graffiti uses orders 0–2 and persistent direct marks begin at 100, so the in-flight stream draws above both kinds of transparent wall paint instead of being hidden where their silhouettes overlap. Normal depth testing remains enabled: opaque room geometry can still hide the stream, so this ordering does not make paint visible through furniture or walls. The three central-wall decorative sprites use 0.78-to-0.82 alpha, reducing competition in the balloon play field while retaining the established room palette; side-wall decoration and geometry are unchanged.

The earlier mesh-head and dual-TrailRenderer projectile presentation remains stored on the legacy prefab but is not used by the current shooter path. The October 24 Editor validation loads the production scene and prefab, checks the serialized density/cone/size/noise/two-frame/sorting settings, simulates nonzero bounded particles, verifies the saved shooter reference and checks the three focus-wall alpha values. C# compilation, Unity import and metadata audit also pass. These are saved configuration and automated Editor evidence, not physical held-fire, complete-song, performance or package acceptance. Confirm uninterrupted visibility across existing graffiti, endpoint alignment, target and beat-cue readability, wall sweeps, rapid aim changes, pause/resume and Retry before accepting the presentation.

The exact prompt, generator mode, source path and SHA-256 are stored beside the image in `Provenance.json`. Static alpha/import checks are recorded in `Verification.txt`; they are not a Unity import test or playtest.
